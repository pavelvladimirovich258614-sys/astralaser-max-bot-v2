# SESSION_HANDOFF — переключение между агентами

> Когда ты переключаешь проект с одного агента на другого (Codex → Kimi, Kimi → Claude Code и т.д.), используй эту процедуру. Иначе новый агент начнёт всё сначала, потеряет контекст и сломает уже сделанное.

## Когда переключать

Симптомы, что пора менять агента:

- ❌ Лимиты текущего агента закончились
- ❌ Текущий агент путается, повторяет ошибки, забывает контекст
- ❌ Текущий агент игнорирует инструкции из AGENTS.md
- ❌ Хочешь сравнить мнение по сложной задаче

**НЕ переключай**, если просто бесишься. Переключение — это потеря 5–10 минут на handoff. Делай это осмысленно.

## Перед переключением (обязательно)

### Шаг 1: Зафиксировать состояние в git

```powershell
cd D:\KLIENT_Zakazi\astralaser-max-bot
git status
git add -A
git commit -m "WIP: <фича> <короткое описание состояния>"
git push origin main
```

**Не уходи в новый чат с незакоммиченными правками** — рискуешь их потерять.

### Шаг 2: Обновить progress.md

Текущий агент должен записать Session Record (см. формат в AGENTS.md, п. 6) с:
- Что сделано
- Evidence (вывод pytest, ruff, mypy)
- Текущие follow-ups
- **Next best action** — конкретное действие, с которого начнёт следующий агент

### Шаг 3: Проверить feature_list.json

- Ровно одна фича со статусом `in_progress`?
- Если фича закрыта на 100% (DoD пройдена) — переведи в `completed` и поставь следующую в `in_progress`.
- Если фича в работе — оставь `in_progress`, но уточни в `progress.md`, какой именно подшаг.

## Открытие сессии у нового агента

### Промпт-открывашка (универсальный)

```markdown
Привет. Ты — со-инженер проекта astralaser-max-bot v2.0. Это бот-магазин для мессенджера MAX.

Перед написанием любого кода выполни следующее:

1. Прочитай AGENTS.md (или CLAUDE.md, если ты Claude Code) в корне репозитория.
2. Прочитай docs/TZ.md (полное техническое задание).
3. Прочитай feature_list.json (реестр фич).
4. Прочитай последний Session Record в progress.md (текущее состояние).

После этого ответь мне на 4 вопроса:
1. Какая фича сейчас in_progress?
2. Что было сделано в последней сессии?
3. Какой Next best action из progress.md?
4. Есть ли блокеры?

Не пиши код, не предлагай новые фичи. Жди моей команды после ответа.
```

### Если агент говорит «не могу прочитать файлы»

Некоторые интерфейсы (AnythingLLM, OpenWebUI и др.) не дают агенту прямой доступ к файловой системе. В этом случае — скармливай файлы текстом:

```powershell
# В PowerShell:
Get-Content AGENTS.md, docs/TZ.md, feature_list.json, progress.md | Set-Clipboard
```

Затем в чате нового агента вставь весь буфер обмена и добавь сверху:

```markdown
Ниже четыре файла из репозитория astralaser-max-bot. Прочитай их по порядку и подтверди готовность работать. Жди моей команды.

═══ AGENTS.md ═══
<вставлен>

═══ docs/TZ.md ═══
<вставлен>

═══ feature_list.json ═══
<вставлен>

═══ progress.md ═══
<вставлен>

После прочтения ответь на 4 вопроса (см. выше).
```

## Особенности конкретных агентов

### Codex (OpenAI)

- Работает в собственном UI (chat.openai.com / GitHub Copilot Workspace)
- Хорошо понимает большие промпты с заголовками `##`
- Любит план перед кодом — **подтверждай план явно** перед запуском
- Может пропустить env-переменные — проверяй `.env` после его правок

### Kimi K2 / K2.6 (Moonshot)

- Контекст 200K — можно скармливать сразу 4 файла + ТЗ
- Инструмент работы: чат kimi.com или через провайдеры
- Иногда «улучшает» соседние файлы без спроса — следи за `git diff`

### GLM-4.5 / GLM-5.1 (Z.AI)

- Доступен через Claude Code как drop-in replacement
- Хорошо следует короткими шагами — не давай задач по 20 пунктов
- Иногда галлюцинирует имена файлов — проси `view` перед редактированием

### DeepSeek V4 Pro

- Силён в анализе и архитектурном review
- Используй как «второе мнение» по AGENTS.md, ТЗ, спорным решениям
- Для основного кодинга — Codex или Kimi

### Claude Code (Anthropic, нативный)

- Запуск через `claude` в терминале (в папке проекта)
- Автоматически читает `CLAUDE.md`
- Отлично ведёт длинные сессии
- Команды: `/init`, `/clear`, `/compact`, прямой вызов tools

### Z.AI GLM через Claude Code

- В `~/.claude/settings.json` конфигурируется как замена Sonnet
- Работает через Anthropic API формат, но под капотом GLM
- Может терять часть инструмент-вызовов — проверяй

## Чек-лист handoff (заполняется человеком)

- [ ] `git status` чистый или закоммичен WIP
- [ ] Push на GitHub сделан
- [ ] Последний Session Record в progress.md актуален
- [ ] feature_list.json показывает реальное состояние
- [ ] Новый агент получил 4 файла (AGENTS.md, ТЗ, feature_list.json, progress.md)
- [ ] Новый агент ответил на 4 вопроса (фича, что сделано, next action, блокеры)
- [ ] Ответы нового агента совпадают с реальным состоянием
- [ ] Только после этого даю новому агенту первую команду на код

## Анти-паттерны (так делать нельзя)

- ❌ «Скопируй мне всю переписку с предыдущим агентом и продолжай» — новый агент захлебнётся в шуме.
- ❌ «Просто продолжай с того места» без проверки источников истины — потеря контекста гарантирована.
- ❌ Не коммитить перед переключением — риск потерять часы работы.
- ❌ Открывать вторую фичу в работу, потому что новый агент «свеженький» — нарушает «одну фичу за раз».
- ❌ Переключаться, пока текущая фича в `awaiting verification` — закрой её сначала.
